# ストア掲載文の書き方

ゲームごとに文面の調子がばらつかないよう、説明書のように遊び方を淡々と書く型にそろえる。

## 書く前に必ずやること

1. **ゲームを実際に把握する**: コード（ルール・入力処理・画面上の文字とボタン）を読むか、実際に遊んで確かめる。仕様書（`docs/` など）があれば読む。推測で書かない
2. **画面上のボタンの名前と位置を確認する**（例: 右上のリセットボタン）。説明文で位置まで書くので、実物と一致させる
3. 書き終えたら、説明文の各文がゲームの実際の挙動と一致しているかを一文ずつ照合する

## 一行説明（Play Console の「簡単な説明」）

- 英語。80 文字以内（目安 35〜75 文字）
- ゲームの手触りを一言で: 何をするゲームか＋何が面白いか。次のどちらかの形にする
  - 動詞から始める: `Tap to <動作> and <目的>!`
  - ジャンルから始める: `A <形容> puzzle game where you <動作>`
- 末尾は「!」が多い。キーワードの羅列、絵文字、"Best" / "#1" などの誇張はしない

## 説明文（Play Console の「詳しい説明」）

**調子**: 平易で事務的な英語。遊び方を順番に淡々と書く。宣伝文句・見出し・箇条書き記号・絵文字・大文字の強調は使わない。
**形**: 1 文 1 行。話のまとまりごとに空行を 1 つ入れる。長さは 300〜1000 文字程度（4000 文字の上限まで書かない）。

この順で書く（該当しない段は省く）:

1. **目的（1〜2 行）**: 次のどちらかの書き出しにする
   - `The objective of the game is to ...`
   - `The board is filled with ...` の後に `The goal of the game is to ...`
2. **基本操作（数行）**: `Tap ... to ...` / `You can ... by dragging ...` の形で、プレイヤーの操作と、その結果何が起きるかを書く
3. **ルール・結果（数行）**: 成功・失敗・特別な場合に何が起きるか（`If ..., ...` / `Any ... will be ...`）
4. **画面のボタン（あれば）**: 位置まで書く。例 `Press the Reset button in the upper-right corner of the screen to restart the level from the beginning.`
5. **クリア条件（必要なら 1 行）**: `Once ..., the level is complete.`
6. **締めの一問（1 行）**: `Can you clear all the levels?` / `Can you complete all the levels?` のような挑戦の問いかけ。または `Put your ... to the test!`

### してはいけないこと

- 機械翻訳ツールの署名などの消し忘れ（例: `Translated with DeepL.com (free version)`）を残す
- 実際の画面に無いボタン・機能・モード（ランキング、ヒント、ライフなど）を書く
- ゲーム内の言葉と違う呼び方をする（ゲーム内で "letters" なら "numbers" と書かない、など）
- 宣伝調の見出し（`FEATURES` など）や箇条書きを入れる

## 出し方

- 一行説明と説明文を、文字数を添えてコードブロックで出す（そのまま Play Console に貼れるように）
- 頼まれたら日本語訳も、行の区切りをそろえて付ける
- Play Console への登録まで頼まれたら、使える手段（Google Play Developer API のツール、または Play Console の画面操作）で入れる。どちらも保存・送信の前に内容を見せて確認を取る
