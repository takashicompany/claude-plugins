# Game Planner スキル

ゲームの曖昧なアイデアから、実装担当（人間でも AI でも）が読んで迷わず作れる仕様書（`plan.md`）を作るスキル。

## スキルの目的と本質

ユーザーが質問に答えていくだけでアイデアが仕様書になることが目的。ただし**固定の質問テンプレートに沿って順番に聞く運用は禁止**する。それでは単なるフォーム埋めになってしまい、AI を使う意味がない。

代わりに、最初の2問だけ固定で投げて方向性を把握した後は、**そのアイデアごとに次に決めるべきことを AI が判定して進める**。

## 仕様書の Definition of Done

`plan.md` が以下を全て満たした時点で完成と判断する:

- このゲームの **コア体験**（プレイヤーが何を気持ちよく感じるか）が一文で言える
- このゲームの **コアループ**（プレイヤーが繰り返す基本サイクル）が説明されている
- **参考ゲームとの差分**（残す部分/変える部分）が明確になっている
- **勝敗条件・終了条件** が定義されている（無いなら「無い」と明記）
- **想定プラットフォームと操作系** が決まっている
- **規模感**（1プレイ尺・全体ボリューム）が決まっている
- 実装担当が読んで「次に何を作るか」が自走判断できる

抜け / 曖昧 / 矛盾があれば未完成。

## 進行手順

### Step 1: 最初の2問（固定・AskUserQuestion）

最初に必ず以下の2問だけ投げる。これは「AI が何を作ろうとしているかを把握する最小限のシード」であり、ここを増やしてはいけない。

**Q1. 一言で説明するとどんなゲームですか？**

選択肢（言語化のテンプレ。回答自体は「その他」で自由記述してもらう）:

- 「[何]を[どうする]ゲーム」（例: 砂を試験管に並べ替えるゲーム）
- 「[誰]が[何]するゲーム」（例: 探偵が謎を解くゲーム）
- 「[既存ゲーム]の[ひねり]版」（例: テトリスの逆再生版）
- その他（自由記述）

**Q2. 参考にしているゲームや類似ゲームはありますか？**

選択肢:

- 具体的なタイトルがある（その他で記述）
- ジャンルだけ思い浮かぶ（その他で記述）
- 特になし（オリジナル）
- その他

### Step 2: 調査（サブエージェント発注）

`game-researcher` サブエージェントを Agent ツールで起動し、Q1/Q2 の回答を渡して以下を取得する:

- 参考ゲーム / 類似ジャンルの基本仕様サマリ
- 同ジャンルで定番化している決定論点
- 差別化ポイントの候補

調査ツールの可用性は **サブエージェントの内部で判定させる**（AppMagic MCP が使える環境では使用、無ければ WebSearch / WebFetch のみで完走）。スキル本体は AppMagic に依存しない。

調査開始前にユーザーへ「これから参考ゲーム/類似ジャンルを調査します」と一言告知する。

「特になし（オリジナル）」と回答された場合は、Q1 の説明文から関連ジャンルを推定して同様に調査する。

### Step 3: 対話ループ（型なし・AI 判定駆動）

Q1/Q2 の回答 + 調査結果を踏まえ、Definition of Done を満たすまで以下のループを回す。

**毎ターン、AI は次のアクションのうちどれを取るかを判定する:**

| アクション | いつ取るか | どう実行するか |
|---|---|---|
| **質問する** | 決めるべきことが特定できた時 | AskUserQuestion。**必ず選択肢を提示**する。選択肢は調査結果や業界の定番から動的生成。常に「その他（自由記述）」を許容。 |
| **追加調査する** | 選択肢を出すための材料が薄い時 / 仕様判断に追加情報が必要な時 | 再度 `game-researcher` を発注 |
| **押し戻す** | 直前の回答が曖昧 / 矛盾 / 抽象的すぎる時 | Socratic に1段だけ具体化を要求（"その『楽しい』は具体的にどんな絵ですか？" のように、選択肢付きの AskUserQuestion で） |
| **書き出す** | Definition of Done が満たされたと判断した時 | `plan.md` を書く（Step 4 へ） |

**判断の指針（順序や項目を強制しない）:**

- **広 → 狭** の方向で進める（コア体験 → コアループ → 詳細）
- **曖昧 → 具体** に降ろす
- **既に答えが出ている事を再度聞かない**
- **決めなくても仕様書が書ける項目はわざわざ聞かない**
- **質問の総数は最小化**する（チェックリスト消化が目的ではない）
- AskUserQuestion は1回最大4問なので、関連質問をまとめて投げてよい

### Step 4: 仕様書の書き出し

`plan.md` を書く。デフォルトのパスは `plan.md`（カレントディレクトリ）。ゲームフォルダが既にある（例: `games/<game-name>/`）場合はその配下に置く。

含めるべき内容（ただし**章立てや構成はアイデアに応じて柔軟に変える**。テンプレ埋めにしない）:

- ゲーム名 / 一言説明
- ゲーム概要
- コア体験（このゲームの売り・気持ちよさの正体）
- コアルール / コアループ
- 参考ゲームとの差分
- 操作 / プラットフォーム
- 進行 / 規模 / メタ要素
- 演出・サウンドの方向性
- 補足

### Step 5: 批評ループ（粗探し）

`plan.md` を書いた後、AI 自身が**粗探し役**として一通り読み返す。観点:

- コア体験とコアループに矛盾はないか
- 参考ゲームとの差分が「リスキンレベル」で止まっていないか
- 実装担当がこれを読んで「ここどう作る？」と詰まる箇所はないか
- Definition of Done を満たしているのに具体性が足りない箇所はないか

問題があれば該当箇所だけ AskUserQuestion で追加質問 → `plan.md` を更新。問題なしなら `plan.md` のパスをユーザーに報告して終了。

## 厳守事項

- **固定の質問リストを順番通りに聞く運用は禁止**（フォーム埋めに堕ちる）
- **既に明らかになっている事項を再度確認するのは禁止**
- **AI が単独で仕様を勝手に決めるのは禁止**（必ず AskUserQuestion 経由でユーザーに選ばせる）
- **AppMagic MCP に依存する設計は禁止**（無くても完走する）
- **質問は必ず選択肢付きで投げる**（自由記述だけの質問は禁止。「その他」で自由記述を許容するのは可）
