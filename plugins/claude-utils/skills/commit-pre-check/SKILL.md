# Commit Pre-Check スキル

現在のgit statusを分析し、ファイルを以下の3カテゴリに分類してください。

## 手順

1. `git status` を実行して変更されたファイルを確認する
2. `git diff` を実行して変更内容を把握する
3. 未追跡ファイルがあれば、その内容も確認する
4. 各ファイルを以下の3カテゴリに分類し、理由を添えて列挙する

## 分類カテゴリ

### コミットしたほうが良いもの
以下に該当するファイルを分類する:
- ソースコードの意味のある変更
- テストコードの追加・修正
- 設定ファイルの意図的な変更
- ドキュメントの更新

### コミットするべきではないもの
以下に該当するファイルを分類する:
- `.env` やクレデンシャルなど秘密情報を含むファイル
- ビルド成果物やキャッシュファイル（`node_modules/`, `dist/`, `__pycache__/` 等）
- OS固有のファイル（`.DS_Store`, `Thumbs.db` 等）
- IDE固有の設定ファイル（`.idea/`, `.vscode/` 等）ただしチームで共有する設定は除く
- ログファイル

### ユーザーに判断してほしいもの
以下に該当するファイルを分類する:
- 意図的な変更かどうか判断がつかないもの
- ロックファイル（`package-lock.json`, `yarn.lock` 等）の大きな変更
- `.gitignore` に追加すべきか判断が必要なもの
- 複数の論理的変更が混在していて、コミットを分けるべきか判断が必要なもの

## 出力形式

以下の形式で出力してください:

```
## コミットしたほうが良いもの
- `ファイルパス` - 理由

## コミットするべきではないもの
- `ファイルパス` - 理由

## ユーザーに判断してほしいもの
- `ファイルパス` - 理由・質問
```

該当ファイルがないカテゴリは「なし」と表示してください。

最後に、コミットを分けたほうが良い場合はその提案も行ってください。
