# html-report

HTML まとめページの入れ物(置き場所・開き方・版の積み方・並べ方・確認)の決まり。
中身(何を書くか・何案出すか・文章・調査の深さ・載せる項目)はこのスキルの対象外。頼まれた内容に従う。

根拠: 直近1ヶ月のまとめページ95個(24プロジェクト)と、関係するセッション98本の会話ログ。

## いつも守る

### 置き方・共有
- **Artifact にしない。** HTML でまとめる = ローカルの HTML ファイルを作ること。
- **サーバー無しで、file:// で直接開ける作りにする。** サーバーを立てるのは、それが無いと実現できない理由があるときだけ(理由をユーザーに言う)。調査のページは特に直開き。
- 見るたびにサーバーの起動・再起動が要る状態にしない。
- データは HTML に埋め込むか、同じフォルダの `data.js` を `<script src>` で読む。`fetch` しない(file:// で動かない)。
- 素材(動画・画像・3D・データ)は、ページと同じフォルダのサブフォルダ(`videos/` `img/` `models/` など)に置き、相対パスで参照する。
- ページのフォルダの外を参照しない(`../` やフルパスで素材を指さない。必要ならフォルダ内にコピーする)。
- ページはプロジェクトの中に置く(一時フォルダに置かない)。本体(ゲーム・アプリ)のコードとは別のフォルダ(`dev/` `docs/` `reports/` `research/` など。プロジェクトに既存の置き場があればそれに合わせる)。
- フォルダごと zip にすれば、そのまま静的ホスティングに上げて動く形にしておく。zip を頼まれたら、作った zip を展開して開けることを確かめてから渡す。
- 外部の CDN・Web フォント・外部画像に頼らない(必要なライブラリはフォルダ内に置く)。
- URL・フォルダ名に `ads` という区切り(`/ads/`)を入れない(広告ブロッカーで白くなる)。

### 開き方・場所の示し方
- **Yaruzo に依存しない。** Yaruzo が無くても見られる・開けること。
- 作ったら見せる。Yaruzo の pane の中で動いていて `yaruzo:open-browser` スキルが使えるならそれで開く(file:// のパスを渡せばよい)。そうでなければ、HTML のフルパスを1行で示す。
- 頼まれていない GUI(macOS の `open`・既定のブラウザ・Finder・Artifact)を開かない。「開いて」の許可はその回だけ。
- 場所はフルパス(URL なら全文)で1行に書く。「上のパス」などで指さない。

### 版の積み方
- 同じテーマの続きは、新しいページを作らず同じページに足す。ファイル名は固定する(版名をファイル名に入れない)。
- 新しいものを上に置く。
- 古い版は消さずに下に残す。絞る・消すのはユーザーが言ったときだけ。
- 版ごとに見出しで区切る(全部を1つのグリッドに混ぜない)。見出しには版名・日時を書く。
- どれが最新か一目で分かる印を付ける(「最新」札・枠など)。

### 並べ方
- 複数の画像・動画・案は、1つずつ開かせず1つの HTML にまとめる(1枚だけの確認なら直接開いてよい)。
- 切り替え式(1つずつ表示)ではなく、一覧で並べて見比べられるようにする。
- 各項目に番号か一意の名前を付け、ファイル名・版名も見せる。会話で「3番」「v2のB」のように指せるようにする。
- 動画は小さめのカードでグリッドに並べる。一覧のサイズで表示し、見切れさせない(縦動画は画面の高さに収める)。
- 頼まれていない機能・見せ方の切り替え・設定 UI を足さない。

### 更新と確認
- 更新したら、確実に最新が見えるようにする。ユーザーに強制再読み込みをさせない。
  - ページの URL は変えない(`?v=` をページの URL に付けない。Yaruzo の open-browser は同じ URL のペインを再読み込みするので、URL を変えるとペインが増える)。
  - 同じ名前のまま中身を差し替えた画像・動画・data.js は、ページ内の参照に `?v=<更新時刻>` を付けるか別名で保存する。
  - サーバーを使うときは `Cache-Control: no-store` を返す。
- 渡す前に、AI が自分で Playwright CLI のヘッドレスで開いて確かめる: 表示されるか・コンソールのエラー0件・参照切れ0件。file:// で開いて確かめる。
  - Playwright MCP やユーザーの Chrome(MCP Bridge)は使わない。
  - ヘッドレスで「Finder で表示」ボタンを押さない(受け口アプリが無いと、ユーザーの画面に macOS のダイアログが出る)。
- 報告には、確かめた範囲と確かめていない範囲を書く。

## 場合に応じて考えること

当てはまるページのときだけやる。

| こういうページなら | やること |
|---|---|
| 比べるページ | 今の(現行・既定の)ものも一緒に並べる。同じ条件(縮尺・カメラ・盤面)で並べる。形の比較なら「並べて/重ねて」の切替 |
| 種類の違うものを載せる | タブや節で分け、混ぜない |
| 項目が多い一覧・表 | 絞り込み・検索・並べ替え・件数表示 |
| 表 | 見出し行を固定、はみ出す分は横スクロール、数字は右寄せ。一度決まった形を勝手に変えない |
| 長い・節の多いページ | 上部に貼り付くページ内ナビ。読み物なら短い版と詳細版に分けてリンク |
| 版を積むページ | 冒頭に「新しいものが上」と書く。版ごとに何を変えたかを一言 |
| 3D を見せる | 回す・切る・透かせるビューア。版はページ内のセレクトで切り替える |
| 画像を見せる | クリックで原寸・拡大 |
| 比べる動画 | `controls` だけ(勝手に同時再生しない) |
| 未完成の欄がある | 空欄にせず「まだ」「何をすれば見られるか」を書く。できたものから載せる |
| データ・調査のページ | 冒頭にデータの出どころ・時点・条件を1行。末尾に出典・生成スクリプトの場所。凡例・数字の意味は記号でなく言葉で |
| 人に渡す・公開する | 認証情報・内部メモ・他社素材を入れない(気になるものは注意を添える) |
| 表示の状態を後で開き直したい | 状態を URL のハッシュに残す |
| HTML を生成スクリプトで書き出した | スクリプトはプロジェクト内に残す |
| チャットで説明に図が要る | 文字の図でなく HTML の図にする |

ダークモード・スマホ幅は、頼まれない限り特別な対応はいらない。

## Finder で表示(ローカルのファイルのフォルダを開く)

動画・画像・3D などローカルのファイルを表示するページには、そのファイルを Finder で選んで表示するボタンを付ける。サーバーは要らない。

仕組み:
- 受け口アプリ HTMLReveal が `htmlreveal://<フルパス>` という URL を受け取り、Finder でそのファイルを選んで表示する(開いたり実行したりはしない)。
- ボタンが出るのは、ページを file:// で開いたときと、Yaruzo の `/api/local-file/` 経由で開いたときだけ。ホスティング先では隠れる。
- HTML には相対パスだけを書く。フルパスは開いた場所から計算する。
- 受け口アプリが無い PC では、ボタンを押すと「Finder を開けませんでした」とパスを横に表示する。クリップボードには書き込まない。

使い方:
1. このスキルの `assets/reveal.js` をページのフォルダにコピーし、`<script src="reveal.js"></script>` で読む。
2. ファイルごとにボタンを置く: `<button data-reveal="videos/a.mp4">Finder で表示</button>`(`data-reveal` はページからの相対パス)。

受け口アプリの導入(Mac ごとに1回。ユーザーの了解を得てから):
- `bash <このスキルのフォルダ>/reveal-app/install.sh` で `~/Applications/HTMLReveal.app` を作って登録する。
- 入っているかの確認: `~/Applications/HTMLReveal.app` があるか。
